# 问卷云：单问题回答与词云控制台方案

版本：v0.2 · 日期：2026-09-10 · 状态：方案阶段，尚未实现应用

仓库：`frozen-s-e-a/wenjuan-cloud`。

部署约束：测试阶段在用户本机完成，正式环境为 2 核 CPU、2 GB 内存的云服务器。便于迁移是首版交付要求：保持同一代码与发布镜像，通过配置切换环境，提供数据备份、恢复及迁移演练。

## 1. 项目目标与边界

构建一个 Web 应用：参与者打开网页只看到一个问题，填写并提交回答；管理员登录独立控制台，查看所有有效回答生成的词云。

第一版默认匿名参与、中文回答为主、同一时间仅开放一个问题。前端具有科技、奇幻、神秘的氛围，视觉主题为“深空中的提问仪式”。

本文件描述拟实现行为，不代表功能已经开发、部署或测试。首版不包含多题问卷、参与者账户体系、AI 情绪判断或严格实名去重。管理员账户及访问验证属于首版必要功能。

## 2. 页面与用户流程

### 2.1 回答页 `/`

全屏布局，首屏可完成回答，不设置导航、营销介绍或他人回答展示。

| 区域 | 设计与行为 |
| --- | --- |
| 背景 | 深蓝黑底色、稀疏星点、低速漂移的紫蓝光雾 |
| 中央视觉 | 细线光环缓慢旋转，营造星际信号入口与奇幻仪式感 |
| 问题 | 居中，视觉优先级最高，中文清晰易读 |
| 回答框 | 半透明深色表面，聚焦时出现青色微光边框 |
| 输入提示 | 默认“输入一个词或一句话”，可由管理员设置 |
| 提交按钮 | 文案“提交回答”，保存成功后触发短暂粒子汇聚动画 |
| 完成反馈 | “回答已收到，感谢参与” |

示例问题：“如果用一个词描述你期待的未来，会是什么？”此题仅为占位示例，实际题目由管理员设置。

支持词语或短句，默认最多 100 个 Unicode 字符；前后端使用一致的长度口径，服务端校验为准。需要更集中词云时，可将提示改为“请输入 1—3 个关键词”。

状态必须完整：

- 加载：获取当前题目；读取失败显示重试入口。
- 未开放：显示“当前暂未开放回答”。
- 输入：纯空白回答不允许提交。
- 提交中：禁用重复提交按钮，保留输入。
- 提交失败：保留原文，提示重试。
- 提交成功：服务器确认事务提交后，显示成功反馈和动画。
- 题目已切换或关闭：服务器拒绝过期提交，保留输入并提示当前题目状态变化，不把回答静默计入新题目。

### 2.2 管理员控制台 `/admin`

登录后访问，布局为：顶部当前问题和收集状态，中间大幅词云，侧边词语排名，下方可展开原始回答。

| 功能 | 行为 |
| --- | --- |
| 问题设置 | 创建题目、设置输入提示、开启或暂停收集 |
| 轮次选择 | 查看当前或历史题目，各轮回答和统计严格分离 |
| 回答统计 | 显示有效回答数、最新提交时间 |
| 动态词云 | 每 5 秒检查统计版本，有更新才刷新布局 |
| 词语排名 | 展示词语及提及回答数，提供精确比较 |
| 回答追溯 | 点击词语，查看贡献该词统计的原始回答，支持分页 |
| 统计调整 | 屏蔽无意义词、配置同义词合并、排除垃圾回答 |

空数据时显示“等待第一条回答”，不展示仿真的词云或虚构统计。统计失败时保留上一次结果并标明更新时间。

更换问题必须创建新轮次；已有回答的题目如需修改实质内容，同样创建新轮次。历史数据保留，避免混合不同问题。

## 3. 视觉规范

| 元素 | 规范 |
| --- | --- |
| 主色 | 深空黑 `#060914` |
| 科技色 | 冰青 `#67E8F9`，用于焦点、交互反馈 |
| 奇幻色 | 紫罗兰 `#9B7BFF`，用于光环与背景光雾 |
| 文字 | 接近白色，核心问题和输入内容保持高可读性 |
| 字体 | 清晰的中文无衬线字体，正文默认不小于 16px |
| 背景动效 | 低速漂移、低密度粒子，不遮挡输入 |
| 提交动效 | 短暂向中心汇聚，保存完成后触发 |
| 词云 | 高频词更大、更亮，低频词分布周围，形成星团感 |

科技与奇幻感由光、空间和几何结构承担，不使用难辨认的装饰字体承载问题。词语以水平排布为主，保持稳定，不持续飞动。

移动端减少粒子数量和装饰层级，保证软键盘弹出后仍可操作。响应系统的减少动态效果设置。装饰层不拦截鼠标和触摸事件；输入框有可访问标签、可见键盘焦点，状态变化可被辅助技术感知。

词云数据变化时使用稳定随机种子和尽量稳定的布局，避免整张图每 5 秒随机跳动。图中显示前 80 个有效词作为初始上限；完整统计通过词语列表分页查看。较大数据量需评估将布局计算移入 Web Worker。

## 4. 词云统计规则

### 4.1 处理流程

1. 保存原始回答及对应轮次。
2. 对用于分析的副本规范空格、标点和英文大小写，原文保持不变。
3. 使用 jieba 分词，结合当前规则版本的自定义短语词典。
4. 过滤“的、了、就是”等停用词及无意义标记。
5. 根据显式同义词映射合并词语，不自动猜测概念是否相同。
6. 对每条回答的归一化词语集合去重。
7. 聚合每个词语的提及回答数。
8. 返回词语、权重及统计版本，前端计算布局并绘制。

### 4.2 计数口径

默认权重为“包含该词的有效回答条数”，不是该词在文本中重复出现的总次数。例如某条回答连续写了十遍“自由”，该回答仍只贡献一次计数。

匿名浏览器标识不等于真实身份，因此界面使用“有效回答数”“提及回答数”，不能将其标为精确参与人数。

示例均为虚构演示数据：

| 回答 | 去重后的分析词语 |
| --- | --- |
| 自由，自由，希望更自由 | 自由、希望 |
| 希望有更多自由和创造力 | 希望、自由、创造力 |

在“希望”未被配置为停用词时，统计得到：自由 2、希望 2、创造力 1。停用词规则由管理员按实际问题调整，调整后重新计算。

### 4.3 语义与可追溯性

词云体现词语热度，不自动代表态度。“希望加班少一点”中的“加班”不能被解释为正面偏好。重要短语可加入词典，存在语义疑问时回看原文。

首版不调用外部大模型；使用规则可控的分词和统计。管理员配置的同义词应保留映射关系，点击归一化词语时能查看所有贡献回答，包括原文使用不同同义表达的情况。

规则有版本号。更新停用词、短语或同义词后，从原始回答重新生成结果；完成前保留旧统计并显示处理中，完成后整体替换，避免混合不同规则版本。

## 5. 技术架构

| 层级 | 技术 | 职责 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite | 回答页、登录、控制台、交互状态 |
| 视觉 | CSS + Canvas | 光环、背景粒子、提交动画 |
| 词云 | d3-cloud + SVG | 碰撞布局、文字绘制、提示与点击 |
| 后端 | FastAPI | 回答提交、认证、题目和统计接口 |
| 数据访问 | SQLAlchemy + Alembic | 数据访问与数据库迁移 |
| 中文处理 | jieba + 版本化规则 | 分词、停用词、短语和同义词处理 |
| 数据库 | SQLite | 首版单机持久化 |
| 部署 | Docker Compose + Caddy + 单进程 FastAPI | 本机与云端共用发布镜像，同源访问及 HTTPS |

前端负责显示，服务器负责保存和统计。所有设备请求同一个后台，数据不能只存储在各自浏览器中。

首版无需 Redis、消息队列或独立数据库服务。SQLite 使用持久化文件、短事务及适当锁等待配置。并发写入或多实例部署需求增长后，再评估 PostgreSQL；规模与性能需以实际压测为依据。

分词在写事务之外完成，并设置有界并发；进入短事务后重新检查题目状态和规则版本，版本变化时按当前规则重试。事务内保存回答及词语贡献、更新数据版本；控制台按轮次和规则版本查询聚合结果。必须避免前端轮询触发对全部原文重新分词。规则重算可使用数据库记录状态的单机任务，异常重启后允许重试。

## 6. 数据模型草案

| 表 | 主要字段 | 说明 |
| --- | --- | --- |
| questions | id、text、hint、status、created_at | 题目及轮次；最多一个处于开放状态 |
| answers | id、question_id、raw_text、participant_hash、request_id、status、created_at | 原始回答、重复请求标识、有效或排除状态 |
| rule_sets | id、question_id、version、stopwords、phrases、synonyms、status | 版本化分析规则 |
| answer_terms | answer_id、rule_set_id、term | 每条回答贡献的归一化词语，同一词只保留一次 |
| admin_users | id、username、password_hash | 管理员身份，不保存明文密码 |
| admin_sessions | id_hash、admin_id、expires_at | 可撤销的服务端登录会话 |

关键约束：

- `answers(question_id, request_id)` 唯一，保证同一次请求重试不会重复入库。
- 默认每轮每个匿名浏览器标识只接受一条回答，通过服务端唯一约束落实；清除浏览器数据或更换设备仍可再次参与。
- `answer_terms(answer_id, rule_set_id, term)` 唯一，保证单条回答重复词不抬高计数。
- 题目切换与提交检查在事务内保证一致，已关闭题目不能继续接收新回答。
- 排除回答后，统计结果同步更新；原文保留用于管理员核查。

## 7. API 草案

具体响应结构在开发时固化；所有 `/api/admin/` 接口执行服务端权限检查，不能只靠隐藏页面入口。

| 方法与路径 | 用途 | 访问条件 |
| --- | --- | --- |
| GET `/api/question/current` | 读取当前开放题目 | 公开 |
| POST `/api/answers` | 提交题目 ID、回答和请求 ID | 公开，服务端校验与限流 |
| POST `/api/admin/login` | 建立管理员会话 | 登录凭据 |
| POST `/api/admin/logout` | 撤销当前会话 | 已登录 |
| GET `/api/admin/questions` | 当前及历史轮次 | 已登录 |
| POST `/api/admin/questions` | 创建新题目轮次 | 已登录 |
| PATCH `/api/admin/questions/{id}` | 开启或暂停收集 | 已登录 |
| GET `/api/admin/questions/{id}/stats` | 统计摘要、词语权重和版本 | 已登录 |
| GET `/api/admin/questions/{id}/answers` | 分页查看原文，可按归一化词语筛选 | 已登录 |
| PATCH `/api/admin/answers/{id}` | 排除或恢复回答 | 已登录 |
| PUT `/api/admin/questions/{id}/rules` | 更新规则并触发重算 | 已登录 |

提交成功返回已持久化的回答标识；相同请求 ID 和相同载荷重复提交返回原成功结果，相同请求 ID 对应不同载荷返回冲突。规则更新与状态变更接口应校验数据版本，防止多个管理页面相互覆盖。

## 8. 数据与访问保护

- 匿名参与无需填写姓名或邮箱；浏览器标识只用于尽力去重，不进行设备指纹追踪。
- 管理员密码使用成熟的密码哈希库；生产管理员密码通过初始化流程设置，不写入代码。
- 管理员采用 HttpOnly 会话 Cookie，公网启用 Secure，结合 SameSite 与写操作的 CSRF 防护。
- 登录与公开提交设置服务端频率限制。限流不能仅按公司出口 IP 一刀切，以免同一 Wi-Fi 的正常参与者被误拦。
- 回答作为纯文本渲染，不执行 HTML；接口限制长度和请求体大小。
- 数据库、备份、回答导出及真实凭据不提交到 GitHub；日志不记录回答正文、密码和会话令牌。
- GitHub 仓库只存源码、方案、配置示例和合成测试数据。

## 10. 本机测试、2 核 2G 部署与迁移

### 10.1 环境一致性

正式部署目标按 Linux 云服务器设计，具体发行版和 CPU 架构在发布前确认。本机如使用 Windows，以 Docker Desktop 的 Linux 容器模式进行最终集成测试；若本机暂不具备容器运行条件，可以原生开发调试，但上线前仍需完成发布镜像验证。

| 项目 | 本机测试 | 云服务器 |
| --- | --- | --- |
| 程序 | 指定版本的发布镜像 | 同一个已验证的发布镜像 |
| 编排 | 共享 Compose + local 覆盖配置 | 共享 Compose + prod 覆盖配置 |
| 入口 | localhost 指定端口，默认 HTTP | 正式域名，HTTPS |
| 运行方式 | 最终验收关闭开发热重载 | 关闭调试与热重载 |
| 数据库 | 独立本机数据目录中的 SQLite | 独立云端数据目录中的 SQLite |
| 参数与凭据 | 本机环境文件 | 独立生产环境文件 |
| 外部依赖 | 运行不依赖开发电脑 | 运行不依赖开发电脑 |

本机原生 Vite/FastAPI 调试作为开发便利方式；“本机测试通过”最终必须指向同一发布镜像，而不仅是开发服务器能打开。

前端 API 一律使用相对路径 `/api/...`，字体和粒子资源随应用打包，不把 localhost、服务器 IP 或域名编译进前端。切换环境无需修改业务代码或重新构建前端。

### 10.2 运行服务与镜像

常驻服务仅保留：

- `app`：一个 FastAPI/Uvicorn 进程，处理接口并提供已构建的前端静态文件；API 路由优先，页面回退仅作用于前端路由。
- `proxy`：Caddy 提供统一站点入口，生产环境处理 HTTPS；app 端口只在容器网络暴露。

使用多阶段 Docker 构建：Node 阶段编译前端，Python 阶段准备后端依赖，最终镜像只包含运行所需的代码、依赖及静态资源。云服务器不常驻 Node 开发服务，不安装 Redis、独立数据库、Celery 或本地大模型。

镜像在本机或 CI 构建，2 核 2G 服务器只负责拉取或导入后运行。每次发布绑定 Git 提交和固定镜像摘要，部署不使用无法追溯的 `latest`。如果本机与云端架构不同，构建目标架构镜像或多架构发布，并在目标架构上验证；不同架构的镜像不能假设字节完全相同。

镜像仓库可用时拉取指定版本；不可用时提供经过校验的镜像归档，通过 SSH 传输并导入。源码拉取不等于安装完成，镜像或完整构建产物必须包含运行依赖。

### 10.3 2 核 2G 资源控制

以下是待验证的初始配置和资源预算，不是已测得占用，也不构成并发承诺：

| 项目 | 初始设计 |
| --- | --- |
| 后端进程 | 1 个 worker，避免多进程重复加载中文词典 |
| app 内存上限 | 暂定 1024 MiB；压测包含启动、规则重算与管理登录峰值后再调整 |
| proxy 内存上限 | 暂定 128 MiB，验证 HTTPS 及正常请求负载 |
| 系统余量 | 不分配满 2 GB，余量供 Linux、Docker、文件缓存与突发使用 |
| CPU | 2 vCPU 为整机预算，分词和规则重算并发有上限 |
| 分词任务 | 短回答处理与批量重算不直接阻塞异步事件循环；重算单任务分批执行 |
| SQLite | WAL、短事务、有界锁等待；位于宿主机本地磁盘，不放网络共享盘 |
| 控制台 | 默认每 5 秒检查更新；后台标签页暂停轮询，失败退避，多请求不重叠 |
| 查询 | 原文和完整排名分页；按题目、状态及词语建立必要索引 |
| 日志与备份 | Docker 日志轮转，备份保留数量可配置，监控磁盘余量 |

词云排布、粒子、光环及动画在访问者浏览器中完成，服务器只发送静态资源及统计数据。浏览器端仍需移动设备验证。

不在低配云服务器上执行前端打包或安装大量构建依赖。不依靠 swap 达成性能验收；如出现内存不足或锁竞争，先测量并减少峰值、批次与并发，再决定是否需要扩容。

### 10.4 配置和持久化约定

共享 Compose 定义与环境覆盖文件分离；所有环境使用相同的容器内路径：

| 配置或目录 | 约定 |
| --- | --- |
| `APP_IMAGE` | 固定版本或摘要的运行镜像 |
| `SITE_ADDRESS` | 本机 HTTP 入口或生产域名 |
| `PUBLIC_ORIGIN` | CSRF 等校验使用的受信站点来源 |
| `COOKIE_SECURE` | 本机 HTTP 可为 false，生产 HTTPS 必须为 true |
| `DATA_DIR` | 宿主机持久化目录，挂载到容器 `/app/data` |
| 数据库路径 | 容器内固定为 `/app/data/app.db` |
| `BACKUP_DIR` | 宿主机备份目录，挂载到容器 `/app/backups` |
| 应用密钥 | 环境独立配置，不写入镜像或提交到 Git |
| Caddy 数据卷 | 持久化证书与相关状态，不随容器重建删除 |

本机与生产分别保存未纳入 Git 的环境文件，仓库仅提供占位配置示例。生产启动时对必需配置、数据库权限及安全 Cookie 设置进行检查，缺失时明确报错。

数据目录挂载整个文件夹，确保 SQLite 的 WAL/SHM 文件与数据库一起持久化。宿主机目录须允许容器运行用户读写；应用不依赖 Windows 盘符、反斜杠路径或用户目录。业务数据不能写入镜像层或源码目录。备份恢复逻辑在容器内统一实现，避免 Windows 与 Linux 各维护一套数据库操作。

### 10.5 从本机迁移到云端

默认正式上线使用干净数据库，仅通过应用提供的导出/导入迁移题目和规则配置，重新初始化管理员，不把演示回答带入生产。若需保留本机已有正式回答，采用下面的完整数据迁移流程：

1. 固定已在本机验收的 Git 提交、镜像版本及数据库迁移版本，记录清单。
2. 将源环境置于维护状态，暂停回答、管理员写入和规则重算，等待在途写入完成。
3. 使用 SQLite Backup API 导出一致性数据库快照，检查完整性，记录回答数、轮次数、规则版本和文件校验和。不得直接只复制运行中的主 `.db` 文件而忽略 WAL。
4. 云服务器准备 Docker/Compose、持久化目录和环境配置，通过 SSH 上传快照，或只导入题目及规则。镜像与业务数据分别传输，备份不经过公开仓库。
5. 在目标 app 停止时恢复数据库；若目标已有数据，先备份目标，禁止静默覆盖。用一次性维护命令执行 Alembic 迁移，成功后才启动服务，失败则保持关闭。
6. 使迁移过来的管理员会话失效，使用正式管理员凭据重新登录。生产密钥独立设置；与历史记录有关的哈希密钥须分类处理，不能随意更换后假设历史匿名去重仍有效。
7. 配置域名与 HTTPS，验证问题、有效回答数、词语排名和原文追溯一致。确认目标可以提交、重启后数据仍存在，再开放正式访问。
8. 源环境保持只读或停止，避免本机与云端同时收集导致数据分叉。

从 localhost 改为正式域名后，浏览器 Cookie 或本地存储通常不会自动迁移，因此“匿名浏览器每轮一次”的限制不保证跨域延续；数据库回答可完整迁移，两者需要分别验收。

### 10.6 升级、回滚和运维

- 升级前短暂维护、暂停写入并生成经校验的备份，记录当前镜像及数据库版本。
- 拉取目标镜像，在应用停机期间单次执行数据库迁移，成功后启动并检查健康状态；不让多个服务并行执行迁移。
- 健康检查至少验证服务存活和数据库可读；备份脚本检查备份可恢复，不只检查文件存在。
- 回滚须验证旧镜像与当前数据库结构兼容；不兼容时恢复升级前快照与旧镜像。正式恢复写入后不能无提示回退旧快照，否则会丢失新增回答，需先保存并处理新增数据。
- 配置容器异常退出重启策略。日常更新不删除数据目录或持久化卷，不以清空数据库解决启动问题。
- 定期通过 SQLite 安全备份方式备份，并保留一份服务器之外的副本；备份包含敏感回答，不公开发布。
- 局域网演示时只在需要时绑定可被其他设备访问的地址，并确认 Wi-Fi 不隔离客户端；正式运行不依赖本机持续开机。

最终程序须包含 Dockerfile、三份 Compose 配置、占位环境文件、本机运行说明、2 核 2G 部署说明、版本化数据库迁移、备份/恢复/校验命令，以及按顺序可执行的迁移与回滚手册。

这些文件和命令当前只是交付要求，方案更新不代表它们已经实现。安装 Docker、主机架构、云端磁盘容量和正式域名在实施前核实；无需为补充方案提前购买或配置服务器。

## 11. 实施顺序

1. 先确定共享 Docker/Compose、配置与持久化目录，再完成数据库、题目读取、回答提交及幂等处理，跑通多设备汇总。
2. 完成管理员登录、轮次管理、原文查看与权限控制。
3. 实现分词、规则版本、提及回答数统计、排名与词云。
4. 完成深空风格、粒子和光环动效、手机适配与状态反馈。
5. 在本机用发布镜像验证关键流程，完成干净目标环境迁移演练和 2 核 2G 资源验证，交付可运行版本及部署、备份与回滚手册。

## 12. 验收标准

- 两台不同设备提交后，后台能汇总两条回答，且题目归属正确。
- 同一请求重复发送只生成一条记录，失败重试不丢失输入。
- 相同词语在单条回答中重复出现只贡献一次计数。
- 控制台正常联网且处于活动状态时，新回答通常在一个约 5 秒轮询周期及处理耗时内反映；不能将轮询间隔作为严格端到端保证。
- 修改规则、排除回答后统计可重算；点击归一化词语可追溯贡献原文。
- 题目切换期间，旧页面不能将回答误计入新题目。
- 刷新页面或重启服务后数据仍存在，备份可恢复。
- 未登录直接请求管理接口无法读取统计和原始回答。
- 手机首屏能看到问题与回答入口，键盘弹出后能提交，无横向溢出。
- 空数据、网络失败、暂停收集等状态有明确反馈；没有虚构数据。

### 部署与迁移专项验收

- 本机启动和生产启动使用同一版本镜像，切换仅修改环境文件和 Compose 覆盖配置，业务代码及前端无需重写。
- 新建干净目标目录或主机，从发布镜像及导出数据恢复；对比轮次、有效回答数、规则版本与词语排名，结果一致。
- 测试数据默认不进入生产；完整数据迁移模式经过单独验证。
- 重建容器和重启主机后数据库仍在；模拟迁移失败时不会开放一个不完整实例。
- 实际云服务器按 2 vCPU、2 GB RAM 验收。本机可先以 Docker/虚拟机总资源约束演练，但不能用本机结果代替目标机器实测。
- 初始压测场景建议为：10,000 条合成历史回答、每秒 5 次提交持续 10 分钟、每秒 20 次提交持续 30 秒，同时开启两个控制台。生成不同有效参与标识，避免限流拒绝被误计为处理成功；题目始终开放。
- 暂定该负载下回答提交 P95 小于 1 秒、无 OOM 重启、无无法处理的数据库锁错误，所有成功确认的回答均已持久化。报告记录延迟、成功率、CPU、峰值内存及磁盘占用；这是待验证目标，不是现有性能承诺，实际活动峰值超过它时需重新压测。
- 另测全量规则重算与新增回答同时发生的情况，确保规则切换和词语计数一致、无内存失控；规则重算期间的延迟单独记录。
- 真实环境演练一次备份恢复和升级失败回滚，记录步骤与结果，才算达到“方便迁移”的交付要求。

关键测试覆盖计数规则、权限、幂等与轮次切换；视觉和移动端在实现阶段实际验证。本方案阶段未运行应用测试。
